按你发在豆包的那份需求 + 5 张 TRAE 截图实现，一个包 dsh-session-suite（Host + Web Client 两半）：

你的要求落地位置
删除会话（永久删磁盘文件）侧边栏会话「⋯」菜单 → 红色「删除任务」→ 二次确认弹窗；先归档（关掉打开的面板），再删日志目录、投影缓存、快照、记忆

核心：回滚到这个节点（对话+文件+记忆）每条最终助手消息后面的 ↺；输入框上方弹出 TRAE 同款行内确认条「确定要回滚到此步骤…」
回滚前自动备份每次回滚先生成 undo 包（文件 + 记忆 + 分叉出的子会话引用），10 分钟可「撤销回滚」
UI：每条消息一个回滚按钮 + 快照管理面板↺ / 🗑 两个按钮；设置最下面新增「会话快照」页（占用大小、锁定、删除、恢复文件、撤销包、记忆账本）
兼容 desktop profile / 重启装法就是 profile 里的一行，状态写进 DSH_HOME/storages，不是内存态

实现上的关键取舍（也是设计里最有争议的一处）：

  • 回滚不是删日志——DSH 的会话日志只追加，删不了。所以回滚 = 先在目标消息的 seq 处 fork（包含该条，同 cwd、同 preset）→ 恢复那一轮的文件快照 → 裁掉晚于该 seq 的记忆 → 归档原会话。TRAE 是「删掉当前会话」，我改成「归档 + 10 分钟撤销窗口」，观感一样但误操作能救回来。
  • 快照是我自己实现的：DSH 自带 workspaceChanges 只在内存和临时目录，会话一 dispose 就没了，无法还原任意时点，所以按设计做了内容寻址的增量存储（manifest 存路径+hash，内容 gzip 后同内容只存一份，未变化靠 size+mtime 跳过）、每会话 10 个自动配额、锁定不参与淘汰、忽略 node_modules/.git/缓存/日志/锁文件。

一、记忆写入触发规则（隐式识别 + 显式指令双模式）

  1. 显式触发（最高优先级）：用户发送【记住：xxx】【新增全局记忆：xxx】【新增本工作区记忆：xxx】，直接写入对应记忆库，跳过初筛，自动打上初始元数据：创建时间、访问次数=1、情感标记、独特性标签。
  2. 隐式自动识别触发：每一轮对话结束后自动执行内容筛查：识别稳定偏好、固定技术约定、长期策略、用户固有习惯；单次临时任务、一次性查询、临时调试、即时闲聊，直接丢弃，不进入记忆库。

隐式识别到可记忆内容后，先给用户预览摘要，询问是否确认存入，用户同意后才入库；用户拒绝则放弃存储，不自动偷偷保存。（和豆包的区别：豆包是后台自动存，DSH保留控制权）

二、第一层：重要性评分 & 遗忘阈值计算（四因子加权模型）

每条记忆入库时附带元数据：创建时间、最后访问时间、访问次数、情感强度标记、内容相似度重复度。
计算公式维度：

  1. 访问频率：被检索调用次数越高，分数越高；长期从来没有被调取的记忆持续降分
  2. 时间衰减：距离【最后访问时间】越久，分数持续衰减（不是单纯按创建时间；只要被调用就刷新衰减时钟）
  3. 情感强度：带有强烈主观偏好、硬性约束、高优先级要求的内容，加权加分；中性无偏好事实分值偏低
  4. 信息独特性：和已有记忆高度重复的内容，自动降分；全新独有的信息加分

设置两级阈值：

  • 低于【删除阈值】：标记为待遗忘，自动移出活跃记忆库，归档到冷存储，不再参与检索召回；
  • 介于【压缩阈值 ~ 删除阈值】之间：标记为待聚类压缩，保留摘要，原始细节归档冷存储；
  • 高于压缩阈值：保留完整原始记忆，活跃检索池。

遗忘逻辑：不是固定90天强制删除，是动态衰减；一条记忆只要持续被你使用，就会“续命”，不会因为时间久被删掉；长期无人问津的低价值记忆慢慢衰减淘汰。

三、第二层：相似聚类 & 摘要压缩

定时扫描记忆库，对语义高度相似的记忆做聚类分组：

  1. 同簇多条原始细节记忆，合并生成一条精简代表摘要，放入活跃记忆池用于召回；
  2. 原始详细原文，移动到冷归档存储；
  3. 用户查询到这条记忆时，可以按需选择：只看摘要，或者调取归档原始细节。

四、第三层：抽象泛化，从情景记忆提炼规则记忆

持续对聚类后的记忆做二次提炼：从多条具体事件、案例里面，提取通用稳定规律，升级为【规则型记忆】，优先级高于零散情景记忆。
