## 二、未完成 / 待办

### P0 — 隐式提取队列（唯一未验证的功能）

**状态**：已修三轮，仍未在真实对话中看到候选。**这是当前最需要解决的一项。**

**已排除的原因**：
| 轮次 | 假设 | 修法 | 结果 |
|---|---|---|---|
| 1 | `config.memoryModels` 为空 | 改为从 Host 的 `llm` 服务枚举 | 模型下拉能看到了，队列仍空 |
| 2 | 默认回退会偷跑 token | 改为显式选择才调用 | 授权问题解决，队列仍空 |
| 3 | 计数器被 reset 清空 | 计数器跨 reset 保留 + 立即发布 | **待验证** |

**当前诊断手段**：界面显示「收到 N 个会话事件 · 结束 M 轮」。

**三种可能**：
1. **N=0** → 监听器根本没触发 → 需换事件绑定方式（可能要用 scoped ctx）
2. **N>0, M=0** → `turn/end` 没被识别 → 需查事件结构
3. **M>0** → 原因会直接显示在界面上

**关键对比**：快照监听器用**同一个** `ctx.on('session/event')` 且工作正常（33 张快照），所以事件**能**收到。这排除了「ctx 没绑上」，指向 trace 发布路径或 early return。

### P1 — 上架 dsh.so 市场

**现状**：`https://cdn.dsh.so/market/index.json` 里有 135 个条目，**没有我们的插件**。

**原因**：dsh.so 是**自动索引**（25,509 个插件），靠扫描 GitHub 和 npm，不是人工收录。

**收录标准**（已逐条核对，我们大部分符合）：
| 要求 | 我们 | 状态 |
|---|---|---|
| DSH 兼容信号：`dsh` 字段 / `cordis` manifest / GitHub topic `dsh-plugin` | 有 `dsh.icon`、`dsh.profile` | ⚠️ 可能不符判定规则 |
| README 有安装说明 | ✅ | ✅ |
| 开源协议 + SPDX | ✅ | ✅ |
| 插件 id slug 合规 | `dsh-session-suite` | ✅ |
| 源码可扫描 | ✅ 纯 JS | ✅ |
| 安全扫描通过 | 未测 | ⚠️ |

**最快的解法**：给 GitHub 仓库加 topic **`dsh-plugin`** —— 文档明确说这会让 registry 自动索引。

**备选**：手动提交到 `https://www.dsh.so/submit/`。

### P2 — 上下文感知检索

**问题**：每轮 `query` 就是当前这句话，不含上文。用户问「那它为什么慢？」，检索不知道「它」指什么。

**为什么暂缓**：需要判断「哪些上文值得拼进 query」。拼少了没用，拼多了稀释。没有可靠判据时贸然实现会退步。

**触发条件**：等有具体失败案例再动手。

### 明确不做（附理由）

| 项 | 理由 |
|---|---|
| 多模态提取 | 成本高；且提取的信息仍会经历压缩与衰减，留不住。图片信息该留在会话里 |
| GraphRAG / RAPTOR | 库只有 50 条个人事实，一层 tag 分组已够。等单工作区超 300 条再考虑 |
| 智能体化 RAG | 固定注入已够用，让 Agent 自己遍历文件是另一种产品 |
| 文档分块 | 记忆不是文档，单条上限 300 字符 |
| 跨用户知识库 | 个人助手，不共享给他人 |
| 会话记忆（面板内） | 已移除。dsh 自带轨迹且不可改，手写笔记是弱副本 |

## 三、已知限制（诚实版）

1. **纯词法检索有盲区**：跨语言同义（checkpoint ↔ 快照）零匹配。dense 重排能缓解，但需用户自装模型。
2. **压缩是追加式的**：回滚是 fork 新会话，不是改写历史。
3. **编辑并重发是追加**，不替换原问题。
4. **隐式提取每轮一次模型调用**：即使选了便宜模型，也是持续成本。
5. **记忆单条上限 300 字符**：长内容必须拆成多条。
6. **面板无工作区概念**：显示的是全部工作区的汇总。

## 五、发布流程（重要）

**规则**：改完 → 发 npm → 用户在插件市场点更新 → 重启。

**不再手动 Copy 文件到 profile**。之前这么做造成了「npm 版本 + 本地补丁」的混合状态，出问题无法判断是哪一版。

**发版后必须验证**：
```powershell
npm view '@heixui/dsh-session-suite' dist-tags
# 确认 latest 指向新版本，npm publish 的 + pkg@ver 不代表已上线
```
