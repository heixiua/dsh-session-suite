## 二、未完成 / 待办

### P1 — 隐式提取队列（正在进行）

**状态**：已修两轮，仍未在真实对话中看到候选。

**已排除**：
- 配置没传（`config.memoryModels` 为空）→ 已改为从 Host 的 `llm` 服务枚举
- 默认偷跑 token → 已改为显式选择才调用
- UI 没有入口 → 已加模型下拉

**当前做法**：在界面上显示诊断计数（收到 N 个会话事件 / 结束 M 轮），下一轮对话后看这两个数字定位。

**三种可能**：
1. 监听器根本没触发 → 收到 0 个事件 → 需换事件绑定方式
2. 有事件但 0 轮结束 → `turn/end` 没被识别 → 需查事件结构
3. 有轮结束但有原因 → 原因会直接显示

**验证方法**：聊 2-3 轮 → 看「待确认的记忆」下方那行计数。

### P2 — 记忆可视化

**要做什么**：面板太素，只有四个数字。加可视化。

**可选内容**：
- 标签分布（哪些主题的记忆最多）
- 分数分布（多少条高分、多少条濒临归档）
- 时间线（近期新增记忆的趋势）
- 库健康度（重复率、归档率）

**参考**：dsh-context 有完整的图表实现（饼图、柱状图、活跃度热力图），可借鉴其视觉语言。

**注意**：不要为了图表而图表。每个图表要回答一个具体问题。

### P3 — 快照孤儿清理

**问题**：`#prune` 只在该会话**再次拍照时**触发。会话被删除或废弃后，它的快照目录（含 blob）**永远没人清理**。

**现状**：实测 8 个快照目录，孤儿 0 个（因为删会话时会清）。但**如果会话被外部删除**（比如 dsh-session-manager），就会留下孤儿。

**要做什么**：
- 加一个 `sweepOrphans()`：扫描 `storages/dsh-session-suite/sessions/` 下所有目录，若对应 sessionId 在 `~/.dsh/sessions/` 里没有日志，则清理
- 接到现有的 30 分钟维护定时器上
- 默认只报告不删除，或加开关

---

### P4 — 上下文感知检索

**问题**：每轮 `query` 就是当前这句话，不含上文。用户问「那它为什么慢？」，检索不知道「它」指什么。

**为什么暂缓**：需要判断「哪些上文值得拼进 query」。拼少了没用，拼多了稀释。没有可靠判据时贸然实现会退步。

**触发条件**：等有具体失败案例再动手。

---

### P5 — 跨工作区会话总表

**状态**：你要求留到后面。

**技术上可行**：直接读 `~/.dsh/sessions/<转义工作区名>/<sessionId>/session.v4.jsonl.zstd`。

**雷点（已查明）**：
1. **隐私**：会话里有私人对话。必须默认只显示摘要（标题+时间+轮次），正文要点开才读
2. **subagent 会话**：必须按 `origin === 'subagent'` 过滤
3. **归档会话**：默认不显示，除非专门筛选
4. **数据量**：上百会话需分页或缓存

---

### 明确不做（附理由）

| 项 | 理由 |
|---|---|
| 多模态提取 | 成本高；且提取的信息仍会经历压缩与衰减，留不住。图片信息该留在会话里 |
| GraphRAG / RAPTOR | 库只有 50 条个人事实，一层 tag 分组已够。等单工作区超 300 条再考虑 |
| 智能体化 RAG | 固定注入已够用，让 Agent 自己遍历文件是另一种产品 |
| 文档分块 | 记忆不是文档，单条上限 300 字符 |
| 跨用户知识库 | 个人助手，不共享给他人 |
| 会话记忆（面板内） | 已移除。dsh 自带轨迹且不可改，手写笔记是弱副本 |

## 三、已知限制（诚实版）

1. **纯词法检索有盲区**：跨语言同义（checkpoint ↔ 快照）零匹配。dense 重排能缓解，但需用户自装模型。
2. **压缩是追加式的**：回滚是 fork 新会话，不是改写历史。
3. **编辑并重发是追加**，不替换原问题。
4. **隐式提取每轮一次模型调用**：即使选了便宜模型，也是持续成本。
5. **记忆单条上限 300 字符**：长内容必须拆成多条。
6. **面板无工作区概念**：显示的是全部工作区的汇总。

## 五、发布流程（重要）

**规则**：改完 → 发 npm → 用户在插件市场点更新 → 重启。

**不再手动 Copy 文件到 profile**。之前这么做造成了「npm 版本 + 本地补丁」的混合状态，出问题无法判断是哪一版。

**发版后必须验证**：
```powershell

# 确认 latest 指向新版本，npm publish 的 + pkg@ver 不代表已上线
```
