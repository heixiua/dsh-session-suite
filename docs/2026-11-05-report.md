### 事实键解决的是什么

词法相似度看不见"值的变化"：「拼团还没开」和「拼团开了」是同一件事的前后却词面不像；「身高一米七」和「长胖到 55 公斤」词面像却是两件事。带 `对象.方面` 键的条目视为同一事实，只召回最新的一条，旧的标记为已取代——**不删除、可查看、可复活**。两条安全规则：太宽的键（单段、通用词）**直接拒绝**，键里**不许写值**。

### 注入策略的改动

`recallLimit` 从"配额"改成"上限"：证据强才给满预算，证据弱就给少，几乎不匹配就只给一条。另加**常驻层**（默认 2 条最重要的记忆，不问自随）——否则像「继续」这种不含任何记忆词汇的追问会突然失去记忆，用户会以为功能坏了。未被注入的候选都会带上原因（`no-match` / `capacity`）。

**在记忆设置页新增「这句话会召回什么？」试算面板**：输入一个问题，直接看到会注入哪几条、证据支持几条、其余各自因为什么被排除。它是**只读**的（`touch: false`），所以用它试算不会改变任何记忆的评分——否则用户"好奇点几下"就会污染自己的排序。

### 顺带修掉的一个真实 bug

给试算面板写 API 契约测试时，发现 `lib/api.js` 的路由处理器写的是 `return respond(...)` 而**不是 `return await respond(...)`**。`respond` 是 async，所以它的 reject **永远不会进入那个 `try/catch`**——服务层抛错（例如"会话正在运行"）会变成未处理的 promise 拒绝，而客户端恰恰依赖 `error.code` 来区分"会话在运行"和一般失败。已修正为 `await`，并加了断言"错误路径必须返回 400 且带 code"的测试。
